# napi (냅냥)

Swagger/OpenAPI 명세와 서버의 접근 로그를 비교해서 **사용되지 않는(잠자는) API**를 찾아 주는 Windows 데스크톱 도구입니다.
낮잠 자는 고양이 냅냥이 안내합니다.

## 설치 및 실행

### exe로 쓰기 (권장)

`dist\napi.exe` 하나만 있으면 됩니다. Python은 필요 없고, 더블클릭하면 창이 열립니다.
Windows 10/11 에는 보통 WebView2 런타임이 이미 들어 있습니다. 없으면 실행 시 안내 창이 뜨니
안내된 주소에서 설치해 주세요.

### 소스에서 실행

```powershell
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
.venv\Scripts\python -m napi
```

Python 3.12 이상이 필요합니다.

## 설정 파일 공유

설정은 `%APPDATA%\napi\napi-config.yaml` 에 저장됩니다 (설정 화면에서 저장하면 생깁니다).
서비스, 서버 주소, 로그 경로, 로그 형식, 판정 기준(임계값), 제외 경로, 메모가 들어 있습니다.

- 팀원과 공유하려면 이 파일을 그대로 전달하고, 받는 사람은 같은 위치에 넣으면 됩니다.
- 파일에 **비밀번호는 들어 있지 않습니다.** 공유해도 안전하지만, 서버 주소와 계정 이름은 들어 있으니 사내에서만 돌려 주세요.
- 비밀번호는 스캔할 때 묻는 창이나 설정 화면에서 입력하며, 프로그램이 켜져 있는 동안 메모리에만 있습니다. 아래 "비밀번호와 키파일"을 보세요.
- `NAPI_HOME` 환경 변수를 지정하면 `%APPDATA%\napi` 대신 그 폴더를 씁니다.

## 보안 원칙

- **원본 로그를 가져오지 않습니다.** 로그 집계는 서버에서 awk로 수행하고, 경로별 호출 수 같은 집계 결과만 내려받습니다. 로그 원문은 서버 밖으로 나가지 않습니다.
- **비밀번호를 저장하지 않습니다.** 설정 파일, 결과 파일, 로그 어디에도 남기지 않습니다.
- **읽기 전용 명령만 실행합니다.** 서버에서는 파일 조회와 집계 명령만 쓰며, 서버의 파일을 만들거나 바꾸거나 지우지 않습니다.
- SSH 호스트 키는 처음 접속할 때 확인을 받아 `%APPDATA%\napi\known_hosts` 에 기록합니다.

## 로그 형식 맞추는 법

설정 화면의 서버 카드에서 **로그 경로마다** 로그 형식을 고릅니다 (경로 줄 오른쪽의 드롭다운).
한 서버에서 접근 로그와 예전 형식의 보관 로그처럼 형식이 다른 파일을 함께 읽을 수 있습니다.
드롭다운에는 기본 제공 형식, 직접 만든 형식(내 형식), `직접 지정 (필드 번호)`가 나옵니다.

| 형식 | 패턴 |
| --- | --- |
| WebtoB (`webtob`) | `%h %l %u %t "%r" %s %b` |
| WebtoB (combined) (`webtob_combined`) | `%h %l %u %t "%r" %s %b "%{Referer}i" "%{User-Agent}i"` |
| Apache (common) (`apache_common`) | `%h %l %u %t "%r" %>s %b` |
| Apache (combined) (`apache_combined`) | `%h %l %u %t "%r" %>s %b "%{Referer}i" "%{User-Agent}i"` |
| nginx (combined) (`nginx_combined`) | Apache (combined)와 같음 |
| 직접 지정 (필드 번호) | 공백(스페이스/탭)으로 나눈 **N번째 필드**를 지정 |

### 내 형식 만들기

설정 화면 왼쪽 아래의 **로그 형식** 탭에서 이름과 패턴으로 형식을 추가, 수정, 삭제합니다.
패턴은 WebtoB/Apache의 `LogFormat` 문법을 그대로 적습니다. 서버의 설정 파일에 있는 `LogFormat` 줄을 복사해 오면 됩니다.

- `%r`: 요청 줄(`GET /path HTTP/1.1`). 따옴표로 감싸야 합니다 (`"%r"`). `%r` 대신 `%m`(메서드)과 `%U`(경로)를 함께 써도 됩니다.
  `%U`는 값의 첫 단어(공백·탭 앞까지)만 경로로 씁니다.
- `%t`: `[10/Oct/2026:13:55:36 +0900]` 같은 시각. `%{%Y-%m-%d %H:%M:%S}t` 처럼 strftime 형식도 됩니다
  (`%Y`, `%m` 또는 `%b`, `%d`가 모두 있어야 날짜로 씁니다. 쓸 수 있는 지시자: `%Y %m %d %H %M %S %b %z %y`).
  Apache의 `%{sec}t`, `%{msec_frac}t`, `%{begin:...}t`, `%{end:...}t` 같은 변형은 쓸 수 없습니다.
  월이 01~12, 일이 01~31을 벗어난 줄은 읽지 못한 줄로 셉니다.
- `%s`, `%>s`, `%<s`: 상태 코드. 없어도 되지만, 그러면 상태가 "상태 미상"으로 집계되고 404 판정(외부 탐색 시도)을 하지 못합니다.
- 그 밖의 지시자(`%h %l %u %b %D %{Referer}i %v` 등)는 자리만 맞추고 값은 읽지 않습니다.
- 필드 사이에는 공백이나 `"`, `[` 같은 구분 문자가 있어야 합니다 (`%h%l` 처럼 붙어 있으면 안 됩니다).
- 패턴의 공백은 줄의 공백 1개 이상과 맞습니다. 요청, 시각, 상태 코드를 다 읽으면 그 뒤는 보지 않습니다.

**요청(`%r` 또는 `%m`+`%U`)과 날짜는 꼭 있어야 합니다.** 이 둘이 없으면 어떤 API가 언제 불렸는지 셀 수 없기 때문입니다.
그래서 WebtoB 에러 로그(`webtob_error`)처럼 요청 정보가 없는 형식은 등록할 수 없고,
"API 호출을 셀 수 없는 형식이에요 (요청/시각 필요)"라는 오류가 납니다. 접근 로그(access log)를 지정해 주세요.

각 형식의 **샘플 줄로 테스트**에 로그 한 줄을 붙여 넣으면 메서드, 경로, 정규화 경로, 상태 코드, 날짜를 어떻게 읽는지 바로 보여 줍니다
(서버에서 로그를 가져오지 않습니다). 서버 카드의 경로 줄마다 있는 **샘플 줄로 형식 테스트**는 그 경로에 고른 형식으로,
아직 저장하지 않은 형식도 그대로 시험합니다.
형식 정의는 설정 파일의 `log_formats`에 함께 저장됩니다. 어느 경로든 쓰고 있는 형식은 삭제할 수 없고
(삭제 버튼 옆에 그 형식을 쓰는 서버가 한 번씩 표시됩니다), 형식 이름을 바꾸면 그 형식을 쓰던 경로도 모두 함께 바뀝니다.

### 직접 지정 (필드 번호)

경로 줄의 형식에서 `직접 지정 (필드 번호)`를 고르면 그 줄 아래에 칸이 열립니다.
메서드, 경로, 상태 코드, 시간이 각각 몇 번째 필드(1부터)인지 입력합니다 (경로마다 따로 정합니다).
새로 설정한다면 **로그 형식** 탭에서 형식을 추가해 쓰는 것을 권장합니다 (필드 번호 방식은 예전 설정 호환용입니다).
경로 필드의 양끝 따옴표는 자동으로 벗겨지고, 시간은 CLF(`10/Oct/2026:13:55:36`) 또는 `yyyy-mm-dd` 로 시작하는 ISO8601 형식이어야 합니다.

### 읽지 못한 줄

형식이 맞지 않는 줄은 건너뜁니다. 건너뛴 줄 수는 스캔이 끝난 뒤 스캔 패널과 HTML/PDF 리포트의 "서버별 수집 결과" 표에
`건너뛴 줄 N` 으로 표시됩니다. 한 서버에서 로그 줄의 20% 이상을 읽지 못하면 결과의 신뢰도가 "낮음"이 되고,
사유에 "로그 형식 설정을 확인해 주세요"가 나옵니다.

경로는 비교 전에 정규화됩니다. 쿼리(`?`, `#`)와 `;세션` 부분을 떼고, 숫자·UUID·긴 해시처럼 보이는 조각은 `{*}` 로 바꿔서
`/users/{id}` 같은 명세 경로와 맞춥니다. 명세의 고정 조각이 같은 규칙에 걸리는 경우(예: `retrieveAccountBalanceV2`, `2024`)에도
`{*}` 와 맞춰집니다. 이때 `{*}` 행이 어느 API인지 가릴 수 없으면(예: `/accounts/retrieveAccountBalanceV2` 와
`/accounts/{accountNo}`) 그 호출을 후보 API 모두에 셉니다. 살아 있는 API를 "잠듦"으로 잘못 보여 주지 않기 위해서이며,
그래서 API별 호출 수의 합이 실제 로그 호출 수보다 클 수 있습니다. 명세의 `HEAD`, `OPTIONS` 메서드는 판정에서 뺍니다.

## 로그 경로 여러 개

서버 카드의 **로그 파일 (glob)과 로그 형식** 에는 경로를 여러 개 넣을 수 있습니다. 한 줄은 `[경로] [로그 형식 ▾] [삭제]` 입니다.
**＋ 경로 추가**로 줄을 늘리면 새 줄은 바로 위 줄의 형식(직접 지정이면 필드 번호까지)을 그대로 물려받습니다.
줄마다 **삭제**로 뺍니다 (마지막 한 줄은 지울 수 없습니다). 예: `/logs/webtob/access.log*`, `/logs/webtob/archive/access.log*.gz`

- 경로마다 `/`로 시작하는 전체 경로를 적습니다. 파일 이름 부분에만 `*`, `?`, `[...]`를 쓸 수 있고,
  디렉터리 부분에는 쓸 수 없습니다. 끝이 `/`로 끝나면(파일 이름 패턴이 없으면) 저장할 수 없습니다.
  디렉터리 부분의 `//`, `/./`, `/../`(같은 파일을 두 번 읽게 됩니다)와 탭·줄바꿈 같은 제어 문자도 저장할 수 없습니다.
- `.gz` 파일도 풀어서 읽습니다.
- 같은 파일이 두 경로 이상에 걸리면(예: `access.log*` 와 `access.log.2026*`) **목록에서 위쪽에 있는 경로의 로그 형식으로 한 번만** 읽습니다.
  파일마다 원하는 형식으로 읽히도록 경로가 서로 겹치지 않게 적어 주세요.
- 경로의 형식이 잘못되면(없는 형식 이름, 필드 번호 누락) 저장할 때 그 경로 줄 아래에 오류가 표시됩니다.
- 일부 경로에서만 파일을 찾지 못하면 나머지 경로로 집계하고, 신뢰도 사유에 "<서버>의 경로 <경로>에서 파일을 찾지 못했어요"가 나옵니다.
  모든 경로가 비어 있으면 신뢰도 사유에 "<서버>에서 로그 파일을 찾지 못했어요"가 나옵니다.
- 설정 파일에는 경로마다 형식이 `log_paths: [{glob, log_format, custom_format}]` 로 저장됩니다.
  예전 설정 파일의 `log_glob` / `log_globs` 와 서버의 `log_format` / `custom_format` 도 그대로 읽고
  (경로마다 서버 형식을 물려받습니다), 저장하면 `log_paths` 로 바뀝니다.

## 비밀번호와 키파일

서버 카드의 **인증**에 따라 설정 화면에서 미리 비밀을 넣어 둘 수 있습니다. 넣어 두면 스캔할 때 묻지 않습니다.

- **비밀번호**: `비밀번호` 칸에 입력하고 **저장**을 누릅니다. 설정이 저장된 뒤에만 프로그램에 전달되고, 전달하는 즉시 칸을 비웁니다.
- **키파일**: `키파일 경로`를 적거나 **키파일 불러오기…** 로 파일을 고릅니다 (경로만 기록하고 파일을 열지 않습니다).
  키에 암호가 걸려 있으면 `키파일 암호(있으면)` 칸에 입력합니다.
- 입력한 값은 **저장되지 않습니다.** 설정 파일, 결과 파일, 화면, 로그 어디에도 남지 않고, 프로그램을 끄면 사라집니다.
- 설정 화면을 다시 열면 넣어 둔 서버에 "이번 실행 동안 입력됨 ✓"가 보입니다. **지우기**를 누르면 메모리에서 지우고,
  다음 스캔에서 다시 묻습니다.
- 비밀번호는 (계정, 호스트, 포트)마다 하나, 키파일 암호는 키파일마다 하나입니다. 같은 계정·호스트·포트(또는 같은 키파일)를 쓰는 서버는
  비밀을 함께 쓰므로, 한 서버에서 지우면 함께 지워집니다.

## 빌드 방법

```powershell
powershell -File scripts\build.ps1            # 단일 exe: dist\napi.exe
powershell -File scripts\build.ps1 -OneDir    # 폴더형: dist\napi\napi.exe
```

- 개발 의존성(PyInstaller, Pillow)은 `.venv` 에 설치되어 있어야 합니다: `.venv\Scripts\pip install -e ".[dev]"`
- 아이콘은 `assets\napi.svg` 를 Pillow로 다시 그려서 만듭니다: `.venv\Scripts\python scripts\make_icon.py` (`assets\napi.ico`).
- `scripts\pyi_shim` 은 빌드할 때만 쓰는 보조 파일입니다. 아래 환경 메모를 보세요.

## 테스트

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = "1"
.venv\Scripts\python -m pytest
```

### 환경 메모: `.txt` 파일을 암호화하는 PC

문서 보안(DRM) 에이전트가 `*.txt` 파일을 암호화하는 PC에서는 패키지의 `entry_points.txt` 를 읽지 못해
pytest 플러그인 자동 로드가 실패합니다. 그래서 테스트는 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` 로 실행합니다.
같은 이유로 PyInstaller 빌드에서도 hook 자동 탐색과 setuptools import가 실패하므로,
`napi.spec` 에서 hook 디렉터리를 직접 지정하고 setuptools를 제외했으며 `scripts\build.ps1` 이 `scripts\pyi_shim` 을 PYTHONPATH에 넣습니다.
이 프로젝트는 `.txt` 파일을 만들지 않습니다. 텍스트 파일이 필요하면 확장자 없이 만드세요.

### 실제 Edge로 PDF 만들기 테스트

PDF 내보내기는 Edge를 headless로 실행합니다. 이 테스트는 기본으로 건너뛰고, 직접 확인할 때만 켭니다.

```powershell
$env:NAPI_RUN_EDGE_TESTS = "1"
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = "1"
.venv\Scripts\python -m pytest tests\test_report.py
```
