# napi 설계 문서

- 작성일: 2026-11-19
- 상태: 검토 반영 완료 (승인 대기)
- 시안: `.superpowers/brainstorm/mockups/napi-look-v3.html` (마스코트, 상태별 표정, 메인 화면, 애니메이션)

## 1. 왜 만드는가

금감원 점검 대응으로 보안팀에 API 목록과 상세 명세를 전달했다. 이 과정에서 "명세에는 있지만 실제로는 아무도 호출하지 않는 API", "deprecated 표시가 있지만 아직 호출되는 API", "명세에 없는데 호출되는 API"를 사람이 일일이 찾기 어렵다는 점이 드러났다.

**napi**(Nap + API, 잠자는 API를 찾아낸다)는 API 명세(Swagger/OpenAPI)와 웹서버 접근 로그를 대조해서, API마다 유지할지 삭제를 권고할지 판단할 근거를 보여 주는 Windows 데스크톱 프로그램이다. 개발자 각자가 자기 PC에서 실행하고, 결과를 화면에서 보거나 HTML/PDF 리포트로 내보낸다.

성공 기준:
- 서비스 하나를 설정해 두면 버튼 한 번으로 "잠든 API / deprecated 잔존 호출 / 문서화 안 된 API" 목록이 나온다.
- 그 결과를 근거(호출 수, 마지막 호출일, 근거가 된 로그 기간)와 함께 보안팀이나 점검 대응 자료로 그대로 넘길 수 있다.
- 쓰는 게 즐겁다. 마스코트 "냅냥"이 이 프로그램의 개성이다.

## 2. 목표 / 비목표 / 하지 말아야 할 것

**목표**
- 서비스 단위 설정: 서비스명, 명세 출처, 서버 여러 대(SSH 접속 정보, 로그 위치, 로그 형식)
- SSH로 운영 서버에 접속해, 서버 안에서 로그를 집계하고 결과만 가져오기
- 명세 경로 템플릿과 로그 경로를 매칭해서 API별 상태 판정
- 상태별 필터링이 되는 결과 화면, HTML/PDF 리포트 내보내기
- 단일 exe 배포

**비목표**
- DB, 서버 설치형 구성, 여러 사람이 공유하는 웹 서비스
- 실시간 모니터링, 주기 실행, 알림
- API를 실제로 삭제하거나 서버 설정을 바꾸는 기능
- macOS/Linux 지원 (Windows 전용)

**하지 말아야 할 것 (기능이 동작해도 이렇게 되면 실패)**
- 원본 로그를 PC로 가져오는 것. 로그 다운로드는 허용되지 않으며, 원본 로그 줄이 한 줄이라도 PC로 넘어오면 안 된다. 쿼리스트링과 경로 안의 ID 값도 서버에서 지운 뒤 넘어와야 한다.
- 비밀번호나 키 passphrase를 디스크에 저장하는 것
- 운영 서버에서 쓰기 명령을 실행하거나, 파일을 만들거나, 프로그램을 설치하는 것
- 스캔이 운영 서버 성능에 눈에 띄는 영향을 주는 것

## 3. 제약

- **SSH 접속:** 개발자 PC에서 `서버:포트`로 바로 SSH 접속한다. bastion이나 게이트웨이는 거치지 않는다. 로그 조회 전용 계정이 따로 있고, 그 계정으로 로그 파일을 바로 읽을 수 있다 (`sudo`/`su` 불필요). 그래서 paramiko exec 한 번으로 처리하는 구조로 충분하다.
- **로그와 서비스의 관계:** 로그 경로 하나에는 애플리케이션 하나의 로그만 찍힌다. 그래서 서비스별로 호스트나 vhost를 거르는 필터는 필요 없다. 한 서비스의 서버 목록에는 같은 계층의 서버(같은 요청을 한 번만 기록하는 서버)만 넣는다. 이 규칙은 설정 화면에 안내 문구로 표시한다.
- **대상 서버:** 전부 Linux다. 서버에 추가 설치는 불가하므로 기본 도구(`sh`, `find`, `gzip`, `awk`, `sort`)만 쓴다. GNU awk 사용을 가정하되, gawk 전용 확장 기능은 피한다.
- **웹서버:** Apache, nginx, WebtoB가 대상이고 WebtoB가 가장 많다. 접근 로그는 서버마다 따로 있다.
- **로그 보관 기간:** 3개월 이상, 길면 1년이다. 회전된 `.gz` 파일도 포함된다.
- **명세 확보:** 운영 Swagger는 대개 막혀 있다. 그래서 테스트 서버의 Swagger URL에서 받거나, 파일로 넣어서 운영 로그와 대조한다.
- **실행 환경:** 사내 Windows 10/11 PC. 사내망이므로 프로그램이 실행 중에 인터넷(CDN 등)에 의존하면 안 된다.

## 4. 접근 방식

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. pywebview + HTML UI (선택)** | Python 백엔드 + WebView2로 HTML/CSS/JS 화면 | 확정된 시안을 그대로 화면으로 사용. 애니메이션이 쉬움. 화면과 HTML 리포트가 같은 컴포넌트를 공유. exe 약 30~40MB | Python과 JS 두 언어. WebView2 런타임 필요 (Win11 및 대부분 Win10에 기본 포함) |
| B. PySide6 (Qt) | 순수 Python 네이티브 위젯 | 언어 하나, 표 위젯이 탄탄함 | 귀여운 디자인 재현 비용이 큼. 리포트를 따로 만들어야 함. exe 100MB 이상 |
| C. Flet | Flutter 기반 Python UI | 모던한 UI | 패키징이 덜 성숙. 표와 PDF는 결국 따로 구현 |

사용자가 **A**를 선택했다. 결과 화면과 리포트의 귀여움이 이 프로그램의 매력이기 때문이다.

로그 수집 방식도 두 가지를 검토했다. 하나는 로그를 PC로 받아서 파싱하는 방식, 다른 하나는 서버에서 집계해 결과만 받는 방식이다. 로그 다운로드가 허용되지 않으므로 **서버에서 집계하는 방식으로 확정**했다.

## 5. 설계

### 5.1 구성

```
napi.exe (PyInstaller)
 ├─ backend (Python)
 │   ├─ config      : napi-config.yaml 읽기/쓰기, 스키마 검증
 │   ├─ secrets     : 세션 동안만 메모리에 두는 비밀번호/passphrase 보관소
 │   ├─ spec        : 명세 로딩 (URL/파일) → 정규화된 API 목록
 │   ├─ collector   : SSH 접속, 서버 측 집계 명령 생성·실행, 결과 파싱
 │   ├─ matcher     : 집계된 경로 ↔ 명세 템플릿 매칭
 │   ├─ classifier  : 상태 판정, 신뢰도 계산
 │   ├─ report      : HTML 단일 파일 생성, PDF 변환
 │   └─ api         : pywebview js_api 로 화면에 노출하는 함수들
 └─ ui (HTML/CSS/JS, 빌드 도구 없음, 외부 CDN 없음)
     ├─ 냅냥 SVG + CSS 애니메이션
     ├─ 사이드바(서비스 목록) / 요약(말풍선+도넛) / 상태 탭 + 표
     └─ 설정 화면, 스캔 진행 화면
```

- **언어와 라이브러리:** Python 3.12, `pywebview`(EdgeChromium 백엔드), `paramiko`, `PyYAML`, `requests`
- **UI:** 바닐라 JS로 작성하고 프레임워크는 쓰지 않는다. 차트는 직접 그린 SVG를 쓴다. *(builder의 판단: 필요하면 Alpine.js 같은 경량 라이브러리를 로컬 번들로 넣어도 된다)*

### 5.2 설정 파일 (`napi-config.yaml`)

- **위치:** 기본은 `%APPDATA%\napi\napi-config.yaml`이다. 화면에서 "설정 파일 열기/다른 파일 불러오기"를 지원해서, 팀원이 같은 파일을 공유해 쓸 수 있게 한다.
- **보관하지 않는 것:** 비밀번호, passphrase는 들어가지 않는다. 키파일은 **경로만** 저장한다.
- **예외 메모:** 예외 처리 메모(유지 사유)도 이 파일에 함께 저장한다. 그래서 파일만 공유하면 메모도 팀원에게 같이 공유된다.

```yaml
version: 1
services:
  - name: 라운드페이 API
    spec:
      type: openapi          # openapi (OpenAPI 3.x / Swagger 2.0 자동 판별)
      source: url            # url | file
      location: https://test-roundpay.example.local/v3/api-docs
    path_mapping:            # 로그 경로 → 명세 경로로 맞추기 위한 보정
      strip_prefix: /roundpay
      add_prefix: ""
    thresholds:
      awake_days: 30         # 최근 N일 내 호출 → 깨어있음
      min_coverage_days: 90  # 로그 기간이 이보다 짧은 서버가 있으면 신뢰도 낮음
    exclude_paths: [/health, /actuator/**]
    servers:
      - name: WAS-01
        host: 10.0.0.11
        port: 22
        user: webtob
        auth: password       # password | key
        key_file: null
        log_glob: /webtob/log/access.log*
        log_format: webtob   # apache_common | apache_combined | nginx_combined | webtob | custom
        custom_format: null  # custom일 때 필드 정의 (5.5 참고)
    notes:
      "GET /v1/settlements/yearly":
        reason: 연 1회 정산용 (1월)
        author: 홍길동
        date: 2026-11-19
```

### 5.3 접속 정보와 보안

- **비밀번호 입력:** 스캔을 시작할 때 서버별로 입력받는다. 같은 계정·호스트를 쓰는 서버끼리는 한 번만 입력해도 된다.
- **보관 범위:** 입력한 비밀번호는 프로세스 메모리에만 있고, 프로그램을 종료하면 사라진다. 프로그램이 켜져 있는 동안은 다시 묻지 않는다.
- **호스트 키 확인:** 서버에 처음 접속할 때 지문을 보여 주고 사용자에게 확인받는다. 확인된 지문은 `%APPDATA%\napi\known_hosts`에 저장한다. 이후 접속에서 지문이 바뀌었으면 경고하고 중단한다.
- **명령 미리보기:** 서버에서 실행될 명령 전문을 스캔 전에 화면에서 볼 수 있다 ("실행될 명령 보기").
- **실행 조건:** 원격 명령은 읽기 전용이고 `nice -n 19 ionice -c3`로 낮은 우선순위로 실행한다. 서버에 파일을 만들지 않는다.

### 5.4 서버 측 집계 (핵심)

SSH exec 한 번으로 다음 파이프라인을 실행한다.

```
find <dir> -maxdepth 1 -name '<glob>' -type f [-newermt <분석 시작일>]
  | 파일마다: gzip -dcf <file>
  | LC_ALL=C awk '<형식별 추출 + 정규화 + 집계 스크립트>'
```

awk는 로그 줄마다 다음을 한다.

1. 형식에 맞게 **메서드, 요청 경로, 상태코드, 시각**을 뽑는다. 파싱에 실패한 줄은 개수만 센다.
2. 경로에서 `?` 이후(쿼리스트링)와 `;jsessionid=...` 같은 matrix 파라미터를 제거한다.
3. 경로 조각 중 ID로 보이는 것은 `{*}`로 치환한다. 숫자로만 된 것, UUID, 16자 이상 hex, 일정 길이 이상의 영숫자 혼합 토큰이 해당한다. *(builder의 판단: 정확한 패턴과 길이는 실제 로그로 튜닝한다)*
4. `(메서드, 정규화 경로, 상태코드 클래스 2xx/3xx/4xx/5xx)` 단위로 **호출 수, 최초 호출일, 마지막 호출일**(YYYYMMDD)을 집계한다.
5. 파일마다 **가장 오래된 로그 날짜와 가장 최근 로그 날짜**, 읽은 줄 수, 파싱 실패 수도 함께 출력한다.

출력량을 제한하는 규칙:
- 상태코드가 404뿐인 경로는 스캐너·봇 노이즈일 가능성이 높다. 이런 경로는 상위 N개(기본 200)만 남기고 나머지는 합계로만 보낸다.
- 전체 출력이 상한(예: 5만 줄)을 넘으면 잘라내고, 잘렸다는 사실을 결과에 표시한다.

**분석 기간** *(제안한 판단)*:
- 스캔할 때 기간을 고른다 (90일 / 180일 / 365일 / 남아 있는 전체). 기본값은 365일이고, 한 서비스 안의 모든 서버에 같은 기간을 적용한다.
- `-newermt`는 파일을 1차로 거르는 용도로만 쓴다. 기간 밖의 줄은 awk가 줄 단위 날짜로 한 번 더 걸러낸다.
- 신뢰도 판단(`min_coverage_days`)은 "선택한 기간"과 "서버에 실제로 남아 있는 가장 오래된 로그 날짜" 중 더 짧은 쪽을 기준으로 한다.
- 요약 문구는 실제 근거 기간에 맞춘다 (예: "N개가 9개월째 자고 있어요").

**운영 부하** *(제안한 판단)*:
- 원격 명령은 `nice -n 19 ionice -c3`로 실행한다.
- 동시에 스캔하는 서버 수는 기본 2대로 제한하고, 설정에서 바꿀 수 있다.
- 서버별 소요 시간을 결과에 기록해서, 다음 스캔 때 예상 소요 시간을 보여 준다.
- 운영팀과 합의한 별도 기준이 생기면 이 값들을 조정한다.

출력은 탭으로 구분된 텍스트이고, PC에서 파싱한다. 서버가 여러 대면 위 동시 실행 제한 안에서 스레드로 병렬 실행한다. 서버별 진행 상태(접속 중 / 집계 중 / 완료 / 실패)를 보여 주고, 취소할 수 있어야 한다.

### 5.5 로그 형식

| 형식 | 기본 레이아웃 |
|---|---|
| `apache_common` | `%h %l %u %t "%r" %>s %b` |
| `apache_combined` | common + `"%{Referer}i" "%{User-agent}i"` |
| `nginx_combined` | `$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"` |
| `webtob` | WebtoB 기본 access log 형식 (Common Log Format 계열). 정확한 기본값은 구현 시 실제 로그 샘플로 확인 |
| `custom` | 시각 필드 위치/형식, 요청줄(`"METHOD PATH PROTO"`) 필드 위치, 상태코드 필드 위치를 지정 |

설정 화면에는 **"샘플 줄로 형식 테스트"** 기능을 둔다. 사용자가 로그 한 줄을 직접 붙여 넣으면 PC에서 파싱 결과를 보여 준다. 서버에서 샘플을 가져오지는 않는다 (원본 로그를 받지 않는 원칙).

### 5.6 명세 로딩

- **지원 형식:** OpenAPI 3.x와 Swagger 2.0을 지원하고, JSON/YAML 모두 받는다. URL이나 파일로 읽는다.
- **추출 항목:** `(메서드, 경로 템플릿, operationId, tags, summary, deprecated)`를 뽑는다.
- **경로 prefix:** OpenAPI 3의 `servers[].url` path나 Swagger 2의 `basePath`는 경로 앞에 붙여서 처리한다.
- **형식 확장:** 명세 타입 선택지는 나중에 다른 형식을 추가할 수 있게 확장 가능한 구조로 둔다. v1은 OpenAPI 계열만 지원한다.

### 5.7 매칭

1. **경로 보정:** `path_mapping`으로 로그 경로를 보정한다.
2. **템플릿 변환:** 명세 템플릿 `/v1/users/{id}`를 조각 단위 패턴으로 바꾼다. 리터럴 조각은 정확히 일치해야 하고, `{param}` 조각은 아무 조각과 일치한다. 로그 쪽의 `{*}`는 param 조각과만 일치한다.
3. **우선순위:** 여러 템플릿에 걸리면 리터럴 조각이 많은 템플릿을 우선한다 (`/users/me`가 `/users/{id}`보다 우선).
4. **메서드:** 메서드까지 같아야 매칭된다. `HEAD`와 `OPTIONS`(CORS preflight)는 판정에서 제외한다.
5. **기타 정리:** 끝 슬래시 차이는 무시한다. `exclude_paths`에 걸리는 경로는 제외한다.
6. **유령/외부 탐색 분류:** 어느 템플릿에도 안 걸린 로그 경로 중 2xx/3xx/5xx가 한 번이라도 있으면 **유령**이다. 4xx만 있으면 **외부 탐색 시도**로 분류한다.

### 5.8 판정

| 상태 | 조건 | 권고 |
|---|---|---|
| 🟢 깨어있음 | 마지막 호출이 최근 `awake_days`일 안 | 유지 |
| 🟡 꾸벅꾸벅 | 호출은 있으나 마지막 호출이 `awake_days`일보다 이전 | 확인 필요 |
| 😴 잠듦 | 분석 기간 전체에서 호출 0건 | 삭제 권고 |
| 🪦 영면 | 명세 `deprecated: true` + 호출 0건 | 즉시 삭제 후보 |
| ⚠️ 잠꼬대 | 명세 `deprecated: true` + 호출 있음 | 호출처 이관 필요 |
| 👻 유령 | 로그에만 있고 명세에 없음 (5.7 기준) | 문서화 또는 차단 검토 |
| 🔎 외부 탐색 시도 | 명세에 없고 4xx만 있음 | 참고용 (판정 대상 아님) |

판정 기준 세부:
- **"호출"의 범위:** 상태코드와 관계없이 요청이 들어온 것을 호출로 센다. 상태코드 분포는 별도로 보여 준다.
- **여러 서버 합산:** 서버가 여러 대면 결과를 합친다. 호출 수는 더하고, 마지막 호출일은 가장 최근 값을 쓴다.
- **신뢰도:** 서버 중 로그 기간이 가장 짧은 것이 `min_coverage_days`보다 짧으면 "신뢰도 낮음"을 표시하고, 어느 서버 때문인지 말해 준다. 접속에 실패한 서버가 있어도 "신뢰도 낮음"이다.
- **예외 메모와 판정:** 메모가 달린 API는 상태는 그대로 두되 "📌 유지 사유 있음" 표시를 붙인다. 요약 말풍선의 "잠든 API" 개수에서는 빼고 따로 센다.

### 5.9 화면

시안 v3 기준이다.

- **사이드바:** 서비스 목록과 서비스별 잠든 API 개수 뱃지(잠듦 + 영면, 메모 달린 것 제외), 미스캔 표시, 서비스 추가.
- **요약 영역:** 냅냥과 말풍선 한 줄 요약(예: "API 161개 중 12개가 1년째 자고 있어요"), 근거 메타정보(로그 기간, 서버 수, 신뢰도 경고, 명세 출처), 상태별 도넛 차트, 스캔/HTML/PDF 버튼.
- **상태 탭:** 전체, 잠듦, 영면, 잠꼬대, 유령, 꾸벅꾸벅, 깨어있음, 외부 탐색 시도. 개수가 함께 표시된다.
- **표:** 메서드, 경로, 상태, 호출 수, 마지막 호출, 응답 분포(2xx/4xx/5xx), 태그, 메모. 검색, 메서드·태그 필터, "메모 있는 것만" 필터, 열 정렬을 지원한다. 행을 클릭하면 상세(서버별 호출 수, 최초/마지막 호출일, summary, operationId)를 보여 주고 메모를 편집할 수 있다.
- **설정 화면:** 서비스, 명세, 서버 CRUD와 "샘플 줄로 형식 테스트", "실행될 명령 보기".
- **스캔 진행 화면:** 서버별 진행 상태와 취소 버튼.

### 5.10 냅냥과 애니메이션

- **그림체:** 사용자의 앱 EarnCat 고양이를 참고했다. 둥근 찹쌀떡 얼굴, 흰 털에 주황 얼룩, 갈색 외곽선, 분홍 볼이 특징이다.
- **기본 모습:** 보라색 방석 위에서 식빵 자세로 낮잠을 자고 코풍선을 분다.
- **평소 애니메이션:** 숨쉬기(살짝 부풂), 코풍선이 커졌다 작아짐, 꼬리 살랑, Zzz가 떠오름.
- **스캔 중 애니메이션:** 눈을 뜨고 콩콩 뛰며, 돋보기를 흔든다.
- **상태별 표정 6종:** 상태 아이콘으로 쓴다 (깨어있음 / 꾸벅꾸벅 / 잠듦 / 영면(천사 링) / 잠꼬대(!? 말풍선) / 유령(투명 점선)).
- **구현 방식:** 모두 인라인 SVG + CSS keyframes로 만든다. `prefers-reduced-motion`이면 애니메이션을 끈다.
- **리소스:** exe 아이콘(.ico)과 창 아이콘은 같은 SVG에서 만든다.

### 5.11 결과 보관과 리포트

- **결과 보관:** 마지막 스캔 결과(집계 결과 + 판정)는 서비스별로 `%APPDATA%\napi\results\<서비스>.json`에 저장한다. 프로그램을 다시 열면 마지막 결과를 바로 보여 준다. 이 파일에는 원본 로그가 없고, 경로와 숫자만 들어간다. DB는 쓰지 않는다. *(제안한 판단, 사용자 확인 필요 시 조정)*
- **HTML 리포트:** CSS·SVG·데이터를 모두 인라인한 단일 파일이다. 표지(냅냥 말풍선 + 요약 + 도넛 + 근거 메타정보)가 먼저 나오고, 상태별 표와 메모가 이어진다. 브라우저에서 열었을 때 상태 필터도 동작한다.
- **PDF 리포트:** 같은 HTML을 인쇄용 CSS로 렌더링한다. PC에 설치된 Microsoft Edge의 headless 모드(`msedge --headless --print-to-pdf`)로 변환한다. Edge가 없으면 HTML을 열고 "인쇄 → PDF로 저장"을 안내한다.

### 5.12 배포

- **빌드:** PyInstaller로 빌드한다. 기본은 onefile `napi.exe`이다.
- **백신 오탐 대응:** onefile은 사내 백신에서 오탐될 수 있다. 그럴 때를 위해 onedir zip 빌드도 같이 만들 수 있게 한다.
- **WebView2 미설치 대응:** WebView2 런타임이 없는 PC에서는 설치 안내 메시지를 띄운다.
