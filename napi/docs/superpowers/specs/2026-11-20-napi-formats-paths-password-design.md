# napi 확장 설계 — 사용자 정의 로그 형식, 로그 경로 여러 개, 설정 화면 비밀번호

- 작성일: 2026-11-20
- 상태: 초안 (승인 대기)
- 기반: `docs/superpowers/specs/2026-11-19-napi-design.md` (v1, main에 병합됨)

## 1. 왜

실제 서버에서 v1을 쓰려고 보니 세 가지가 맞지 않았다.

1. **로그 형식이 서버마다 다르다.** WebtoB만 해도 `webtob`, `webtob_combined`, `webtob_error`처럼 여러 형식이 있고, 앞으로 또 늘어난다. 형식을 코드에 미리 넣어 두는 대신 **사용자가 직접 형식을 정의해서 추가**할 수 있어야 한다.
2. **한 서버에 로그 경로가 여러 개다.** 지금은 서버당 glob 하나만 지정할 수 있다.
3. **비밀번호를 설정 화면에서 넣을 곳이 없다.** 지금은 스캔을 시작할 때 뜨는 창에서만 입력한다. 설정 화면에서도 입력할 수 있어야 한다. 단, 저장하지 않고 프로그램이 켜져 있는 동안만 쓴다.

## 2. 목표 / 비목표 / 하지 말아야 할 것

**목표**
- Apache `LogFormat` 문법으로 로그 형식을 정의, 추가, 수정, 삭제하고, 샘플 줄로 바로 테스트한다.
- 서버마다 로그 경로(glob)를 여러 개 지정한다. 형식은 서버당 하나로, 그 서버의 모든 경로에 똑같이 적용한다.
- 설정 화면의 서버 카드에서 비밀번호(또는 키파일 암호)를 입력한다. 메모리에만 두고, 이미 입력됐는지 여부만 표시한다.

**비목표**
- 정규식 기반 형식 정의
- 경로마다 다른 형식 지정
- 비밀번호 저장 (OS 자격 증명 저장소 포함)

**하지 말아야 할 것**
- v1의 보안 원칙을 깨는 것.
  - 원본 로그가 PC로 넘어오면 안 된다.
  - 비밀번호가 디스크, 결과, 응답, DOM 속성에 남으면 안 된다.
  - 원격 명령은 읽기 전용이어야 한다.
- 기존 설정 파일(`log_glob` 하나, `log_format: custom` + `custom_format`)이 깨지는 것
- 형식을 잘못 정의했을 때 조용히 "전부 잠듦"이 나오는 것

## 3. 접근 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. LogFormat 문자열 (선택)** | 사용자가 `%h %l %u %t "%r" %s %b`처럼 적는다. PC가 이를 단계별 파싱 코드로 바꾸고, awk 코드와 Python 기준 파서를 같은 정의에서 만든다. | 사용자가 이미 이 문법으로 형식을 알고 있다. WebtoB, Apache, nginx 설정과 1:1로 대응한다. POSIX awk의 `index`/`substr`만으로 구현할 수 있다. |
| B. 정규식 | 캡처 그룹으로 필드를 뽑는다. | POSIX awk에는 캡처 그룹이 없다(gawk 확장 금지). 그래서 서버 쪽 구현이 어렵다. |
| C. 필드 번호 지정 (v1 `custom`) | 공백으로 나눈 필드 번호를 적는다. | `%t`처럼 공백이 들어간 필드를 다루지 못한다. 사용자가 직관적으로 쓰기 어렵다. |

사용자가 형식을 LogFormat 문법으로 제시했으므로 A를 쓴다.

## 4. 설계

### 4.1 형식 정의 (설정 파일)

```yaml
log_formats:                       # 사용자 정의 형식 (팀 공유)
  - name: webtob_error_req
    pattern: '[%{%Y-%m-%dT%H:%M:%S}t] [CLIENT(%h)] %* "%r" %s'
services:
  - ...
    servers:
      - name: WAS-01
        log_globs:                 # 여러 개 (v1의 log_glob 하나도 계속 읽음)
          - /webtob/log/access.log*
          - /webtob/log/access_ssl.log*
        log_format: webtob_combined   # 기본 제공 또는 log_formats의 name
```

- **기본 제공 형식 (수정 불가, 항상 존재):**
  - `apache_common` = `%h %l %u %t "%r" %>s %b`
  - `apache_combined` = 위 + ` "%{Referer}i" "%{User-Agent}i"`
  - `nginx_combined` (apache_combined와 같음)
  - `webtob` = `%h %l %u %t "%r" %s %b`
  - `webtob_combined` = `%h %l %u %t "%r" %s %b "%{Referer}i" "%{User-Agent}i"`
- **이름 규칙:** 사용자 정의 형식의 이름은 기본 제공 이름과 겹칠 수 없고, 서로 중복될 수 없다.
- **삭제 제한:** 서버가 쓰고 있는 형식은 삭제할 수 없다. 삭제하려 하면 "사용 중인 서버: …"를 안내한다.
- **v1 호환:**
  - `log_glob: x`를 읽으면 `log_globs: [x]`로 바꾸고, 저장할 때는 `log_globs`로 쓴다.
  - `log_format: custom` + `custom_format`도 계속 읽는다. 해당 파서는 유지하되, 새 UI에서는 "직접 지정(필드 번호)" 대신 형식 정의를 추가하도록 안내한다. *(제안한 판단: v1 custom 파서는 호환용으로만 남긴다)*

### 4.2 지원하는 지시자

| 지시자 | 의미 | 파싱 방식 |
|---|---|---|
| `%h %l %u` | 클라이언트, ident, user | 다음 리터럴 직전까지 (공백 없는 토큰) |
| `%t` | `[dd/Mon/yyyy:HH:MM:SS +zzzz]` | 대괄호 포함, 날짜 추출 |
| `%{strftime}t` | 예: `%Y-%m-%dT%H:%M:%S` | 리터럴 경계까지. `%Y %m %d` 위치로 날짜 추출 (`%b` 월 이름 지원) |
| `"%r"` | 요청줄 | 따옴표 안을 v1 규칙으로 토큰화 (메서드 + 경로) |
| `%m`, `%U`, `%q`, `%H` | 메서드, 경로, 쿼리, 프로토콜 | `%r`이 없을 때 `%m`+`%U` 조합 사용 |
| `%s`, `%>s` | 상태코드 | 3자리 숫자 |
| `%b %B %D %T %{X}i %{X}o %*` 및 알 수 없는 지시자 | 건너뛰기 | 다음 리터럴 직전까지. 따옴표로 감싸져 있으면 닫는 따옴표까지 |

- **파싱 방식:** 리터럴(공백, `[`, `]`, `(`, `)`, `"` 등)은 현재 위치에서 정확히 맞아야 한다. 하나라도 맞지 않으면 그 줄은 `parse_fail`이다.
- **필수 조건:** `%r`이 있거나 `%m`과 `%U`가 함께 있어야 하고, 날짜를 담은 시각(`%t` 또는 `%Y %m %d`를 포함한 `%{…}t`)도 있어야 한다. 없으면 저장할 때 "API 호출을 셀 수 없는 형식이에요 (요청/시각 필요)"를 띄운다.
  - 사용자가 준 `webtob_error` (`[%{…}t] [CLIENT(%h)] %*`)는 요청 정보가 없어서 그대로는 등록할 수 없다. 메시지 안에 요청이 일정한 모양으로 찍힌다면 그 모양을 형식에 적어 등록한다. *(사용자 확인 필요 — 승인 시 함께 확인)*
- **상태코드가 없는 형식:** 허용한다. 상태 클래스는 `"???"`로 집계하고, 화면에는 "상태 미상"으로 표시한다. 404 판정과 외부 탐색 분류에서는 404가 아닌 것으로 취급한다(유령 쪽).

### 4.3 컴파일과 동등성

- **컴파일:** `napi/logformat.py`에 `compile_format(pattern) -> FormatSpec`를 둔다. 결과는 토큰 목록(리터럴 / 필드 종류)과 검증 오류다.
- **Python 기준 파서:** `parse_line`이 FormatSpec을 해석한다. 정규화는 v1 규칙 그대로다.
- **awk 생성기:** `awk_program`이 같은 FormatSpec으로 POSIX awk 파싱 코드를 생성한다. `index`/`substr`만 쓰고, 정규화와 집계, 출력 프로토콜, 토큰 마커는 v1 그대로다.
- **동등성 테스트:**
  - 기본 제공 형식 5개 + 테스트용 사용자 형식 2개(`[CLIENT(%h)]` 리터럴 포함, `%{…}t` + `%m %U` 조합)에 대해, v1처럼 awk 출력과 Python 집계가 바이트 단위로 같은지 확인한다.
  - 기존 CLF 경로를 이 엔진으로 옮긴 뒤에도 v1 픽스처의 결과가 바뀌지 않아야 한다(회귀 테스트).

### 4.4 로그 경로 여러 개

- **모델:** `ServerConfig.log_globs: list[str]` (1개 이상). 각 glob은 v1 `split_glob` 검증을 그대로 거친다.
- **원격 명령:** `find`를 glob마다 실행하고 결과를 합친다. `sort -u`로 중복 파일을 제거한 뒤 v1과 같은 파일 루프에 넣는다.
- **E 줄:** `E\tno files matched`는 모든 glob을 합쳐 파일이 0개일 때만 낸다. 파일이 0개인 glob이 일부만 있을 때는 `E\tglob_empty\t<glob>`를 낸다. 신뢰도 사유에는 "<서버명>의 경로 <glob>에서 파일을 찾지 못했어요"를 넣는다.
- **UI:** 서버 카드의 "로그 파일 (glob)" 칸을 목록으로 바꾸고, "＋ 경로 추가"와 경로별 삭제(마지막 1개는 삭제 불가)를 둔다.

### 4.5 설정 화면 비밀번호 (세션 전용)

- **입력 칸:** 서버 카드에 `auth: password`면 "비밀번호", `auth: key`면 "키파일 암호(있으면)" 칸을 둔다(`type=password`, `autocomplete=off`). 안내 문구: "저장되지 않아요. 프로그램을 끄면 사라져요".
- **키파일 지정:** `auth: key`일 때 "키파일 불러오기…" 버튼으로 파일 선택 창을 연다(새 API `pick_key_file() -> {ok, path}`, 기존 대화상자 주입 방식 재사용). 고른 파일의 **경로만** `key_file`로 설정 파일에 저장하고, 키 내용은 읽지도 복사하지도 않는다. 경로 칸은 직접 입력도 가능하다. 스캔할 때마다 그 경로에서 키를 읽는다(v1과 같음).
- **전송 시점:** 설정을 "저장"할 때, 칸에 값이 있는 서버만 `set_password` / `set_passphrase`로 보낸다. 보낸 뒤 칸을 비우고 JS 참조도 버린다. 설정 파일에는 쓰지 않는다.
- **입력 여부 표시:** 새 API `secret_status(service) -> {server: "set" | "missing" | "n/a"}` (값은 절대 반환하지 않음). 서버 카드에 "이번 실행 동안 입력됨 ✓"을 보여 주고, "지우기" 버튼으로 해당 비밀만 메모리에서 지운다(새 API `clear_secret`).
- **스캔 시 동작:** v1처럼 `missing_secrets` 기준으로 빠진 서버만 묻는다. 설정에서 이미 넣었다면 스캔할 때 다시 묻지 않는다.

## 5. 범위와 진행

- **규모:** 작은 프로젝트 하나. 구현 계획(작업 4~5개)을 쓰고, v1처럼 작업마다 구현 → 리뷰 → 수정을 거친다.
- **진행 환경:** 브랜치 `feat/formats-paths-password`. 테스트는 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`로 돌리고 Edge는 실행하지 않는다.
- **builder에게 맡기는 부분:**
  - `%{strftime}t`에서 지원할 지시자 범위의 세부 (`%Y %m %d %b %H %M %S %z` 정도)
  - 형식 관리 UI의 배치
  - 오류 문구의 세부
