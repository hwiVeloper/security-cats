# napi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** napi는 Swagger/OpenAPI 명세와 운영 서버 접근 로그를 대조해서 "잠든 API"를 찾아 주는 Windows용 exe다. 로그 집계는 서버 안에서 SSH로 실행한다.

**Architecture:**
- **백엔드 (Python):** 설정 → 명세 로딩 → SSH 원격 집계 → 매칭 → 판정 → 결과 JSON 순서로 처리한다.
- **화면:** pywebview(WebView2)에 HTML/CSS/JS를 띄운다. JS는 `js_api`로 백엔드를 호출한다.
- **리포트:** 화면과 같은 `render.js`/`app.css`를 단일 HTML에 인라인한다. PDF는 Edge headless로 만든다.

**Tech Stack:**
- Python 3.12, pywebview 5.x, paramiko 3.x, PyYAML 6.x, requests, pytest, PyInstaller 6.x
- 프런트엔드는 바닐라 JS (빌드 도구 없음, CDN 없음)

**Spec:** `docs/superpowers/specs/2026-11-19-napi-design.md` (계획과 함께 반드시 읽을 것)

## Global Constraints

- **원본 로그 금지:** 원본 로그 줄은 PC로 절대 넘어오지 않는다. 원격 명령의 stdout은 아래 "원격 출력 프로토콜"에 정의된 집계 줄만 낸다.
- **비밀 저장 금지:** 비밀번호와 passphrase는 디스크·로그·결과 JSON 어디에도 쓰지 않는다. `SessionSecrets` 메모리에만 둔다.
- **원격 명령 조건:** 원격 명령은 읽기 전용이고, 서버에 파일을 만들지 않는다. `nice -n 19`로 실행하고, `ionice -c3`는 있으면 붙인다. 전체를 `timeout <remote_timeout_sec>`로 감싼다.
- **대상 서버 도구:** Linux, GNU 도구만 쓴다 (`sh`, `find`, `gzip`, `awk`, `sort`, `head`, `timeout`). gawk 전용 확장 기능은 쓰지 않는다 (`asort`, `gensub`, `strftime` 등 금지).
- **파일 위치:**
  - 설정 파일: `%APPDATA%\napi\napi-config.yaml`
  - 호스트 키: `%APPDATA%\napi\known_hosts`
  - 결과: `%APPDATA%\napi\results\<safe_name>.json`
- **기본값:** `awake_days=30`, `min_coverage_days=90`, `max_parallel_servers=2`, `default_window="365"`, `remote_timeout_sec=3600`, `max_rows=50000`, `top_404=200`
- **분석 기간 선택지:** `"90" | "180" | "365" | "all"`
- **판정 제외 메서드:** `HEAD`, `OPTIONS`
- **사용자에게 보이는 문구:** 한국어로 쓴다. 상태 이름은 `깨어있음 / 꾸벅꾸벅 / 잠듦 / 영면 / 잠꼬대 / 유령 / 외부 탐색 시도`를 쓴다.
- **외부 자원 금지:** UI와 리포트는 외부 네트워크 자원(CDN, 웹폰트)을 쓰지 않는다.
- **디자인 기준:** 마스코트와 화면은 `.superpowers/brainstorm/mockups/napi-look-v3.html`을 기준으로 한다. SVG, 색, 애니메이션 keyframes는 이 파일에서 그대로 옮긴다.

### 원격 출력 프로토콜 (Task 4·5가 공유)

탭(`\t`)으로 구분된 줄들이다. 첫 칸이 줄의 종류를 나타낸다.

| 태그 | 칸 | 의미 |
|---|---|---|
| `F` | path, min_date, max_date, lines, parse_fail, out_of_range | 파일별 통계. 날짜는 `YYYYMMDD`이고, 줄이 없으면 `-` |
| `R` | method, path, status_class, count, first, last | 집계 행. 404만 있는 키는 여기 넣지 않는다 |
| `P` | method, path, count, first, last | 404만 있는 키의 상위 `top_404`개 (count 내림차순) |
| `Q` | distinct, count | `P`에서 잘린 나머지 404 전용 키의 합계 |
| `T` | max_rows | `R` 행이 `max_rows`를 넘어 잘렸다는 표시 |
| `E` | message | 원격 측 오류 (예: `no files matched`) |
| `D` | `done` | 정상 종료 표시. 이 줄이 없으면 실패로 처리 |

### 경로 정규화 규칙 (awk와 Python twin이 똑같이 구현)

1. `?` 또는 `#`부터 끝까지 제거한다.
2. 각 조각의 `;` 이후를 제거한다.
3. 연속된 `/`를 하나로 합친다.
4. 끝의 `/`를 제거한다 (루트 `/`는 유지).
5. 조각이 다음 중 하나면 `{*}`로 치환한다.
   - `^[0-9]+$`
   - UUID `^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$`
   - `^[0-9a-fA-F]{16,}$`
   - `^[0-9][0-9-]{5,}$` (전화번호·카드번호 형태)
   - `@` 포함
   - `%` 포함 + 길이 20 이상
   - 길이 20 이상 + 영문과 숫자 모두 포함 (`^[A-Za-z0-9_-]{20,}$` 중 숫자를 포함하는 것)

## Review Focus

1. **깨진 요청줄:** `"-" 400`이나 TLS 바이너리 쓰레기(`"\x16\x03\x01..."`) 같은 줄은 `parse_fail`로 세고, 스캔은 계속된다. → Task 3·4 테스트
2. **한글·퍼센트 인코딩 경로:** `/v1/검색/%ED%99%8D...`처럼 비ASCII나 긴 인코딩 경로가 있어도 정규화가 죽지 않는다. 긴 인코딩 조각은 `{*}`가 된다. → Task 3 테스트
3. **서버 한 대 실패:** 접속 실패, 인증 실패, 타임아웃이 난 서버가 있어도 나머지 서버 결과는 나온다. 신뢰도는 "낮음"이 되고, 사유에 서버명이 들어간다. → Task 6·8 테스트
4. **명세 오류:** 명세 URL 접속 실패, JSON/YAML이 아님, Swagger 2와 OpenAPI 3 혼동, `servers[0].url`이 절대 URL인 경우를 처리한다. 앞의 셋은 한국어 오류 메시지를 내고, 절대 URL은 path만 prefix로 쓴다. → Task 2 테스트
5. **로그 파일 없음:** glob에 걸리는 파일이 없거나 전부 기간 밖이면 그 서버는 `ok=True`, 행 0개다. 신뢰도 사유에 "로그 파일 없음"이 들어간다 (잠듦이 잘못 쏟아지는 것 방지). → Task 4·8 테스트

### Task 3: 로그 형식, Python 파서 twin, 경로 정규화

**Files:**
- Create: `napi/logformat.py`, `tests/fixtures/logs/webtob_access.log`, `tests/fixtures/logs/nginx_access.log`, `tests/fixtures/logs/apache_common.log`

**Interfaces:**
- Consumes: `CustomFormat`
- Produces:
  - `PRESETS: dict[str, str]`. 표시명 매핑: `{"apache_common": "Apache (common)", "apache_combined": "Apache (combined)", "nginx_combined": "nginx (combined)", "webtob": "WebtoB", "custom": "직접 지정"}`

  - `parse_line(line: str, fmt: str, custom: CustomFormat | None = None) -> ParsedLine | None`. 실패하면 `None`. 반환하는 `path`는 정규화 전 원문이다.

명령 구조. 모든 사용자 값은 `shlex.quote`로 감싼다.

```sh
NAPI_TOKEN=<token> timeout <sec> nice -n 19 $(command -v ionice >/dev/null 2>&1 && echo ionice -c3) sh -c '
  find <dir> -maxdepth 1 -type f -name <pattern> [-newermt <since-YYYY-MM-DD>] 2>/dev/null | sort |
  while IFS= read -r f; do printf "\001F\t%s\n" "$f"; gzip -dcf -- "$f" 2>/dev/null; done |
  LC_ALL=C awk -v SINCE=<since|0> -v MAXROWS=<n> -v TOP404=<n> <program>'
```

- `find`에 걸리는 파일이 없으면 awk END에서 `E\tno files matched`를 낸다.

- 집계 키는 `method SUBSEP path SUBSEP status_class`로 만든다. 별도 배열 `non404[method SUBSEP path]`로 404가 아닌 응답이 있었는지 기록한다.
- END에서는 다음을 낸다.
  - `F` 줄들
  - `non404`가 있는 키의 `R` 줄. `MAXROWS`를 넘으면 `T`를 낸다.
  - 404 전용 키는 `print | "sort -t '\t' -k4,4nr | head -n " TOP404`로 `P` 줄을 내고, 나머지 합계를 `Q`로 낸다.

- `coverage_days`는 성공한 서버마다 `(until - max(since, oldest_date))`의 일수를 구한 뒤 그 최솟값이다. 성공한 서버가 없으면 0이다.
- 아래 사유 중 하나라도 있으면 `level="low"`이다.
  - `coverage_days < min_coverage_days` → `"<서버명>은 로그가 <N>일치뿐이에요"`
  - 실패한 서버 → `"<서버명> 스캔 실패: <error>"`

  - 파일이 없는 서버 → `"<서버명>에서 로그 파일을 찾지 못했어요"`

요약 문구:
- `coverage_days >= 360`이면 `"1년째"`, 그렇지 않으면 `coverage_days // 30`개월째다. 30일 미만이면 `"<N>일째"`다.

- `sleeping == 0`이면 `"API {total}개 모두 깨어 있어요! 🐾"`
