# 변경 내역

## v1.2.0

### 입력
- [서버 설정] > 서버 정보 위에 '서비스 계정 절대 사용 금지, 인프라팀을 통해 개인 계정으로 로그 접근 권한을 받아 사용' 주의 문구
- 비밀번호·API 키·인증 토큰 칸은 영문·숫자·기호만 입력 (한글은 막고 안내, 칸에 들어가면 한글 입력기를 영문으로)

### 이메일 보내기 (선택)
- 사내 메일 API(POST /email/send)로 점검 결과 보내기: 회신 요약을 본문으로, HTML 보고서를 첨부(Base64)
- [서버 설정] > 이메일 탭: 발송 주소, 인증 토큰(암호화 저장 가능), 발신자, 기본 받는 사람·참조, 성공 응답 코드, [시험 메일 보내기](발신자·받는 사람을 그때 입력)
- 켜면 결과 화면의 [회신 요약 복사]가 [이메일 보내기]로 바뀜. 보내기 창에서 받는 사람·제목·본문 확인·수정, [본문 복사]
- 제목·본문 개인정보 가림(규격 필수), 첨부 한도(파일 10MB·전체 20MB) 확인, 감사 로그에 건수·주문번호·거래번호만 기록
- 메일 본문은 HTML: 전할 말, 요약 카드, 조회 기간·서버 상태, 로그가 발견된 IP 표(위험도 높은 순), 첨부 안내. 보내기 창에서 미리보기
- 기본 발송 주소 `https://internal.mailapi.com`, 기본 받는 사람 `security@foo.bar`
- 규격 공통 요청 헤더: `Authorization`(발급받은 토큰), `appServiceSeq`(서비스코드, 설정 필수), `apiVersion`(1.0 고정)
- 성공 응답 코드 기본 `0`, 숫자는 값으로 비교 (`0`·`0000`·숫자 0 모두 성공)
- 이메일을 켜면 발신자·기본 받는 사람(필수)과 기본 참조의 주소 형식을 검사해, 비었거나 틀리면 [저장]되지 않음
- 보내기 전에도 AI 분석을 하지 않은 IP가 있으면 분석할지 물음 (보고서 저장과 같은 흐름: 진행 창, 중지, 다시 시도)
- 보고서 파일 이름 기본값 `IPtrace_점검결과_날짜_시각.html`, 이메일 첨부 파일 이름은 제목 앞말을 붙여 `[IPtrace]점검결과_날짜_시각.html` (보내기 창에서 바꿀 수 있음)
- 이메일 전할 말 기본값: "정보보안팀에서 전달받은 침해의심 IP의 서버 접속 기록을 확인한 결과를 공유드립니다."

## v1.1.0

### 점검
- 서버에서 거르기: 로그 전체를 PC로 받지 않고, 서버에서 `zcat | grep -F`로 의심 IP가 든 줄만 받음
- 서버 부하 제한: 가장 낮은 우선순위(`nice`·`ionice`), 파일 하나당 서버 작업 시간 제한(기본 180초), 파일당 최대 10만 줄, 같은 장비의 계정은 차례로 점검
- 조회 기간: [오늘] [어제] [7일] [직접]. 서버 점검은 최대 7일 (로컬 폴더 점검은 제한 없음). [직접]은 달력과 짧은 입력(10/21, 1021, 어제)을 지원
- 로그 경로마다 로그 형식 지정 (접근 로그·에러 로그·WAS 로그를 한 서버에서), WebtoB 에러 로그 형식 기본 제공
- 계정별 서버 항목 ([+ 같은 서버에 계정 추가]), 계정 잠김 방지 (틀린 비밀번호는 다시 보내지 않음)
- 형식과 맞지 않는 줄도 의심 IP와 정확히 맞으면 결과에 '해석 실패'로 넣음

### 결과·보고서
- [보고서 저장]: HTML 보고서가 기본 (파일 하나, 브라우저로 열림, IP를 누르면 로그·AI 분석 펼침, 등급 필터·검색, 인쇄). Excel도 선택 가능
- [회신 요약 복사], [점검 이력] 탭 (요약·근거 위치·검토 상태·메모. 로그 원문은 저장 안 함)

### AI 분석 (선택)
- 사내 AI 게이트웨이(OpenAI 호환·Anthropic)로 고른 IP의 로그를 보내 요약·공격 의도·성공 가능성·추가 확인·권고 조치를 받음
- 보내기 전 토큰·세션·주민번호 등 민감값 가림, 처음 보낼 때 확인, 감사 로그에는 내용 없이 기록만
- 보고서를 저장할 때 아직 분석하지 않은 IP를 같이 분석 (진행 창, 중지, 실패한 IP 다시 시도)
- 위험도 판정은 탐지 규칙 기준. AI 분석은 참고용

### 설치·빌드
- `build_exe.bat`: 소스 점검(doctor) 후 exe 빌드
- `doctor.bat`: 빠진 파일·설정 오류·문서 보안(DRM) 암호화 점검
- `make_release.bat`: GitLab Release에 올릴 zip과 릴리스 설명 만들기
